# liability.py

`liability.py` answers one question: does this binder's own charge threaten the cage's K_CK? `scan_liability` walks a sequence, flags every acidic residue (D/E) that isn't in the caller-supplied `preserve_positions` (the target-contact interface you've decided to protect), totals a kcal/mol penalty (0.8 per residue by default, calibrated in `calibration.py`), and converts that penalty into an estimated weakened K_CK. `suggest_variant` goes a step further and actually proposes the fix, substituting every flagged residue per a chosen policy (`"neutralizing"`: D/E→A, or `"conservative"`: D/E→N/Q) and re-scoring the result. This reproduces ECLIPSE's real documented fix exactly: the charged original binder scans 6 liabilities, a 4.8 kcal/mol penalty, and an estimated K_CK about 3300x weaker than the clean reference (1e-8 → 3.32e-5); the neutralizing substitution restores K_CK to ~1e-8.

The single most important thing to know about this module: mutation positions in the output (like `"D4A"`) are always local to whatever sequence string was passed in, never translated to where that binder sits inside a larger assembled sequence. `liability.py` has zero awareness that `assembly.py` or absolute assembly coordinates exist at all, so any caller checking these mutations against something like SmBiT's absolute-coordinate protected region must apply the offset itself (`binder_start_in_assembly - 1`, added to every local position) before the check means anything. Skipping that step doesn't error, it just silently produces a coincidental pass or fail. Separately, an earlier version of this project's source PDFs misstated the charged binder's K_CK as ~3e-12; the correct value, confirmed by hand and now pinned by tests, is 3.32e-5.
